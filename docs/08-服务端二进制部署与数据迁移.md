# 08 - 服务端二进制部署与数据迁移

面板（`moon`）是**单二进制 + SQLite + 前端 embed** 的自包含程序（ADR-5）：纯 Go 静态编译、无任何外部依赖（无 Redis/MQ/外部数据库），一条命令即跑。Docker 镜像是可选便利形态，**命令行/二进制部署完全对等支持**。

实测资源占用：单二进制 14.5MB；空闲物理内存 13~14MB，含节点心跳与浏览器会话的生产态一般 20~40MB；前端静态资源按需读取不占常驻内存。

---

## 1. 目录与启动规范

### 1.1 目录布局（推荐）

```
/opt/moonshepherd/
├── moon                 # 面板二进制（linux amd64/arm64 静态编译）
├── data/                # 数据目录：herd.db + master.key（备份 = 这两个文件一起拷）
│   └── distro-bin/      # Agent 分发二进制（可选：herd-linux-{amd64,arm64,armv7}，install.sh 下载源）
└── moonshepherd.service # systemd 单元（仓库 packaging/ 附带）
```

### 1.2 启动命令

```bash
./moon server --data /opt/moonshepherd/data --addr :8080
```

### 1.3 完整参数表

| 参数 | 说明 |
|---|---|
| `--data <dir>` | 数据目录（`herd.db` + `master.key`；默认 `./data`） |
| `--addr <addr>` | 监听地址（默认 `:8080`） |
| `--tls-cert` / `--tls-key` | 公网直跑 TLS（建议前置反代代替，见 §4） |
| `--dist-dir <dir>` | Agent 二进制分发目录（默认 `./distro-bin` 或环境变量 `HERD_DIST_DIR`；`install.sh` 与 `/dist/herd-linux-*` 的下载源，**目录缺省时 install.sh 下发不可用，面板其余功能不受影响**） |
| `--trust-proxy` | 前置反代时必须（环境变量 `HERD_TRUST_PROXY=1` 等价；信任 `X-Forwarded-Proto`，docs/05 §3.1） |
| `--admin-password <pwd>` | 首次初始化管理员密码；缺省生成随机密码打印一次（**已有数据的库不会重复初始化**） |
| `--dev` | 开发模式（本地 http、Cookie 不加 Secure；生产禁用） |

子命令：`moon admin reset-password [--data dir] [--user name] [--new-password pwd]`（忘记管理员密码的自救入口）。

### 1.4 systemd 部署

仓库 `packaging/moonshepherd.service` 为配套单元文件（Restart=always / RestartSec=5 / TimeoutStopSec=10）：

```bash
useradd -r -s /sbin/nologin moonshepherd
chown -R moonshepherd:moonshepherd /opt/moonshepherd
cp packaging/moonshepherd.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now moonshepherd
journalctl -u moonshepherd -f        # 首次启动日志（或打印初始密码）
```

升级 = 替换 `moon` 二进制 + `systemctl restart moonshepherd`。SQLite schema 由程序启动时自动增量迁移（含老库补列），跨版本数据无需手工处理。

## 2. 数据迁移说明

### 2.1 迁移物 = data 目录四件（缺一不可）

| 文件 | 作用 |
|---|---|
| `herd.db` | 全部业务数据：用户（登录密码）、节点（含加密连接凭据）、指令历史、操作审计、应用清单、MCP Keys、配置版本、注册 Token、指标 |
| `herd.db-wal` / `herd.db-shm` | WAL 预写日志及伴随文件——**未合并的最近写入在这里**，源端非优雅停机（进程被强杀）时必须一起带；新机首次打开自动回放合并 |
| `master.key` | 节点凭证加密密钥（32 字节）。**缺失则 nodes 表的加密凭据全部无法解密，所有节点需重新注册** |

登录会话不迁移（内存态，面板重启本即失效）——迁移后用**原 admin 用户名密码**登录。

### 2.2 迁移步骤（源：任意形态；目标：ECS 二进制部署）

```bash
# —— 源端（以 Docker 部署的 NAS 为例）——
docker stop <面板容器>                       # 优雅停止;若 exited(137) 强杀,WAL 四件必须全带
tar czf moonshepherd-migrate.tar.gz -C <data目录> herd.db herd.db-wal herd.db-shm master.key
scp moonshepherd-migrate.tar.gz user@<ecs>:/tmp/

# —— 目标端（ECS）——
mkdir -p /opt/moonshepherd/data && cd /opt/moonshepherd/data
tar xzf /tmp/moonshepherd-migrate.tar.gz     # 四件落在 data/
chmod 600 master.key                          # 凭证密钥收紧权限
# 放置二进制与 unit(见 §1.4)后:
systemctl enable --now moonshepherd
```

### 2.3 迁移后验证清单

1. 浏览器登录：沿用**源面板原 admin 密码**（users 表随库迁移）；
2. 「节点」页：原节点列表完整（名称/标签/版本）；节点状态初始显示迁移前快照，Agent 改指新地址重连后刷新为在线；
3. 「操作审计」「指令」历史可查（43 条审计 / 12 条指令等原样保留）；
4. Agent 发起 `probe` 探测成功（`POST /nodes/{id}/probe`）。

### 2.4 Agent 切换指向（凭据不变，无需重新注册）

节点的注册身份（node_id + 密钥）在迁移中保持不变，仅改面板地址即可重连：

| 形态 | 修改位置 |
|---|---|
| 裸二进制（Unraid，`herd-workdir/conn_script.sh`） | 脚本内 `HERD_SERVER=wss://<新面板地址>/agent` 后重跑脚本 |
| systemd 二进制（标准 Linux） | unit 文件 `Environment=HERD_SERVER=wss://<新面板地址>/agent` 后 `systemctl restart herd` |
| （历史）Docker 容器 | 已裁撤——改用 install.sh 以二进制形态重新接入 |

### 2.5 回滚

迁移是**拷贝而非移动**：源端 data 目录原地未动。云侧异常时，源端 `docker start <面板容器>`（或原 systemd 服务）即回滚，节点把 `HERD_SERVER` 改回原地址即可。

## 3. 公网部署安全要点（详见 docs/05）

1. **TLS 必须**：前置反代（Caddy/Nginx，推荐）时面板加 `--trust-proxy` 或 `HERD_TRUST_PROXY=1`；无反代则 `--tls-cert/--tls-key` 直跑——面板在非 TLS 且非本机来源时会拒绝敏感请求；
2. 防火墙仅放行面板端口（与 SSH），Agent 全程只出不进；
3. `master.key` 与 `herd.db` 权限收紧（`chmod 600 master.key`），备份同样加密保管；
4. 数据保留策略：心跳指标 7 天自动清理（docs/01 §7），审计与指令不可删除。

## 4. 日常运维速查

| 操作 | 命令 |
|---|---|
| 查看日志 | `journalctl -u moonshepherd -f` |
| 重启 | `systemctl restart moonshepherd` |
| 备份 | 停止服务后打包 `data/`（或 SQLite 在线备份工具），`herd.db` 与 `master.key` 一起 |
| 忘记密码 | `./moon admin reset-password --data ./data --user admin --new-password <新密码>` |
| 确认版本 | `./moon version`（或面板「系统」页查看） |
