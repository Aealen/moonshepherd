# 牧云 Herd · 迭代路线图

> 版本：v0.1（设计稿） · 日期：2026-10-25
>
> 姊妹文档：[01-产品总体设计](01-产品总体设计.md) · [02-技术选型与工程结构](02-技术选型与工程结构.md) · [04-通信协议规范](04-通信协议规范.md) · [05-安全设计](05-安全设计.md)

## 1. 迭代总览

| 阶段 | 目标 | 一句话边界 |
|---|---|---|
| **P0（MVP）** | 两台真实节点（Unraid + 阿里云 ECS）跑起来，日常运维动作全部面板化 | 纳管、感知、执行、配置下发四件事闭环 + 公网安全基线 |
| **P1** | 好用与安全增强 | 容器操作、自更新、日志流、TOTP、历史曲线、应用变化检测 |
| **P2** | 生态与对外发布 | Unraid 插件、多用户、批量下发、面向用户的开源发布 |

**安全是贯穿约束**：面板将部署于公网、产品将供用户管理其公网机器（见 [05-安全设计](05-安全设计.md) §1），因此公网安全基线是 **P0 出口条件**，不随功能妥协。

## 2. P0（MVP）边界

### 2.1 必须有（Definition of Done）

**节点纳管**

- 注册 Token 发放/撤销；Agent 注册换发节点身份（协议见 [04](04-通信协议规范.md) §2）
- 形态：F1（二进制 + systemd）、F2（Docker 容器）；install.sh 自动探测 systemd / 无 systemd 环境（F3 顺带覆盖）
- 心跳 30s，3 周期超时判 offline；断线指数退避重连

**应用感知**

- 探测器 4 个：`docker` / `nginx` / `caddy` / `systemd`（`unraid` 探测器 → P1）
- 定时探测默认 5 分钟 + 面板手动触发即时探测；探不出明确上报 `unknown`
- 应用中心：跨节点"谁装了什么" + 单节点应用清单

**远程执行**

- 指令 3 种：`exec` / `probe` / `config.apply`
- 异步回执（accepted → result）；全量审计，`commands` 表不可删除

**配置管理**

- 单节点、单文件目标的版本化下发
- 全流程：备份 → 原子写入 → 本地校验 → 重载 → 失败自动回滚（[01](01-产品总体设计.md) §6）
- nginx / caddy 内置 validate / reload 命令

**面板**

- 单管理员（bcrypt + 服务端会话）
- 页面：登录、节点列表/详情、应用中心、指令中心、配置管理、系统（面板信息 + 审计查看，见 [06](06-面板API与页面设计.md)）
- 节点详情展示心跳快照（CPU/内存/磁盘/网络单点值；历史曲线 → P1）

**安全（公网部署基线，详见 [05](05-安全设计.md)）**

- 全链路 TLS 强制；一次性注册 Token；节点身份 HMAC 挑战认证（[04](04-通信协议规范.md) §2）
- **登录防爆破**：IP + 账号双维度限流锁定（P0，不是可选项）
- 节点凭据 AES-256-GCM 加密落库；会话 HttpOnly/Secure/SameSite
- 面板操作审计 + 指令审计；安全响应头（CSP/HSTS）

**分发**

- `herd` / `shepherd` 二进制：linux amd64 + arm64（`shepherd` 另含 armv7）
- `herd-panel` / `shepherd` Docker 镜像；install.sh 统一入口

### 2.2 明确不做（推迟去向见 §3 / §4）

- `docker.op`、`agent.update`、`log_tail`（→ P1）
- TOTP、监控历史曲线、local-agent 模式（→ P1）
- 应用变化检测与通知、配置多文件/模板变量（→ P1）
- F4 `.plg` 插件、多用户 RBAC、配置批量下发（→ P2）

## 3. P1

| 项 | 内容 | 来源 |
|---|---|---|
| docker.op | 容器启停/重启/日志（白名单操作集，不支持任意 docker 命令） | 01 §3.4 |
| agent.update | 二进制形态自更新（sha256 强制校验 + 原子替换）；容器形态升级编排 | 01 §3.5 |
| log_tail | 容器/服务日志流，分片推送 | 04 §6 |
| TOTP | 管理员二步验证 | 05 §3.2 |
| 监控历史曲线 | `metrics` 时序的 ECharts 展示 | 01 §4.1 |
| local-agent | 面板机纳管：面板所在宿主机以标准独立 Agent 进程接入（与远程节点同构，决策见 §6.2） | 01 §4.2 |
| unraid 探测器 | 扫描 /boot/config/plugins 上报插件清单 | 01 §3.3 |
| 应用变化检测 | 应用新增/消失留痕 + 面板通知（当前 `app_inventory` 为覆盖式更新，无历史） | 设计检查新增 |
| 配置增强 | 多文件目标（nginx conf.d 目录）、配置模板/变量 | 设计检查新增 |
| node_secret 在线轮换 | 旧 secret 认证通道下发新 secret，免重注册 | 04 §2.4 |

## 4. P2

| 项 | 内容 |
|---|---|
| F4 Unraid 原生插件 | `.plg` + Community Applications 分发 |
| 多用户与 RBAC | `users.role` 落地，权限模型设计 |
| 配置批量下发 | 同一配置多节点编排、灰度发布 |
| 告警通道 | webhook 通知（应用变化/节点离线/指令失败） |
| ACME 自动证书 | 有公网域名时面板自动申请续期（加分项，非核心功能，决策见 §6.2） |
| 对外发布准备 | 面向用户的开源发布：文档站、demo、镜像加速通道、发布合规检查（**由开源决策触发，暂缓**） |

## 5. P0 内部里程碑（建议顺序）

| # | 里程碑 | 内容 | 验收标准 |
|---|---|---|---|
| M1 | 协议与骨架 | `internal/protocol` 按 04 定稿；WSS 网关、注册/认证/心跳 | shepherd 完成注册 + 认证重连；伪造凭据被拒 |
| M2 | 感知 | docker 探测器 + 应用清单上报 + 应用中心页 | 节点 A（Unraid）容器清单出现在面板 |
| M3 | 执行 | exec + 指令中心 + 审计 | 跨节点命令、异步回执、历史可查、不可删除 |
| M4 | 配置 | config.apply 全流程 + 版本管理页 | **故意下发坏配置 → 校验失败自动回滚成功** |
| M5 | 安全加固与分发 | 05 的 P0 基线全部落地；install.sh、镜像、交叉编译 | 公网部署演练通过 05 §5 checklist |

M2 起前端与后端可并行开发；M4 是安全关键里程碑，回滚机制不完备不得进入 M5。

## 6. 风险与待定项

### 6.1 风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 配置下发破坏在线服务 | 高 | 回滚机制先于功能（M4 验收强制含失败用例） |
| 公网面板遭爆破/扫描 | 高 | 05 §3.2 限流锁定（P0）；文档建议叠加 VPN / Cloudflare Access |
| 面板失守导致全节点沦陷 | 高 | 凭据可撤销 + 全量审计；P2 指令签名/审批（05 §4） |
| BusyBox 环境探测器/执行器降级失效 | 中 | 多级降级 + `unknown` 上报；M2 即上 Unraid 真机验证 |
| WSS 长连接 NAT 超时断连 | 中 | 心跳保活 + TCP keepalive + 指数退避重连（04 §3） |
| modernc.org/sqlite 纯 Go 驱动成熟度 | 低 | 社区活跃；锁定已验证版本 |

### 6.2 决策记录（2026-10-25 老大拍板，原待定项全部清零）

| 项 | 决策 | 备注 |
|---|---|---|
| 产物分发通道 | **GitHub Releases + sha256sums 起步**；大陆加速通道遇到实际拉取慢再补 | Releases 资产下载免费、无流量计费（单文件 <2GiB）；用户量小时零成本 |
| local-agent 构建形态 | **独立进程**：面板机直接跑标准 shepherd，与远程节点完全同构 | 不采用进程内嵌（library）方案，避免面板对 Agent 代码的编译耦合与"本机特有 bug" |
| TLS 证书策略 | **主推前置反代**（证书用户自管）；面板 P0 支持手动证书兜底公网直跑；**ACME 自动为 P2 加分项** | 证书不是产品核心功能；底线不变：公网部署必须有 TLS |
| 对外发布（开源） | **先自用**，合适时机由老大触发开源 | P2 的"对外发布准备"随之启动，暂缓 |
| 产品域名 | 随开源决策再定 | 暂不投入 |
| 撞名检查结论 | 无同领域撞名，可继续用 Herd；开源时以"牧云 Herd + 副标题"区隔 | 已知重名者均跨领域：Laravel Herd（PHP 本地开发环境）、seveas/herd（并行 SSH 客户端）、herd-core/herd（microVM 编排）等 |
