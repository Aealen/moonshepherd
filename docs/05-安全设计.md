## 1. 部署场景与安全定位

本产品的真实部署形态决定安全标准：

- **面板部署于公网可达位置**——它是 Agent 主动外连的汇聚点，天然是一个公网服务，是第一攻击面；
- **Agent 运行于公网服务器与家庭内网机器**——面板一旦失守，所有受管节点即横向扩散目标；
- **产品将提供给其他用户管理其公网机器**——本产品的安全缺陷会直接传导到使用者的服务器上。

因此定两条总原则：

1. **按公网产品级标准设计**，不按"自用内网工具"标准放水；
2. **默认配置即安全（secure by default）**——TLS、防爆破限流、凭据加密、审计全部开箱默认开启，不依赖用户"记得去改配置"。

## 2. 威胁模型

**资产**：管理员账户、节点凭据库、指令通道（本质是全节点 RCE 能力）、配置文件内容、审计记录。

## 3. 分层防御

### 3.1 传输与边界

- WSS/HTTPS 全 TLS 强制；`ws://` 明文仅允许绑定 `127.0.0.1` 的调试模式
- 证书策略（决策见 [03](03-迭代路线图.md) §6.2）：**主推前置反代**——用户已有 Nginx/Caddy，证书自管（目标用户群体的普遍习惯）；面板 P0 原生支持**手动证书**（指定 cert/key，兜底无反代的公网直跑场景）；ACME 自动签发为 **P2 加分项**
- 底线：公网部署必须有 TLS（前置反代或面板自带证书二选一）
- 面板对外**单端口**收敛：Web UI 与 Agent WSS 网关同端口不同路径（如 `/` 与 `/agent`）
- 不开放任何跨域；HTTP 严格跳转 HTTPS

### 3.2 面板认证与会话（→ T1/T2）

| 项 | P0 设计 |
|---|---|
| 口令存储 | bcrypt（cost ≥ 10）；首次启动强制设置管理员密码，最短 10 位 |
| **防爆破** | **IP + 账号双维度限流**：15 分钟窗口内 5 次失败 → 锁定 15 分钟，连续触发锁定时长指数升级；全部落审计并计入面板首页告警 |
| 会话机制 | 服务端会话：随机 256bit 会话 ID，Cookie 属性 `HttpOnly + Secure + SameSite=Strict`；绝对过期 12h、空闲过期 2h；登出即焚；不支持"记住我"长票 |
| CSRF | SameSite=Strict 为主；状态变更接口仅接受 POST/PUT/DELETE，拒绝 GET 副作用 |
| 安全响应头 | CSP（限制 script-src 为 self，禁内联）、HSTS、X-Content-Type-Options: nosniff、Referrer-Policy |
| P1 增强 | TOTP 二步验证、异地/新设备登录通知、会话管理页（可强制下线） |

### 3.3 节点身份与指令通道（→ T3/T5）

- 完整机制见 [04](04-通信协议规范.md) §2/§4，要点：一次性注册 Token（24h/单次/可撤销）→ node_secret；连接认证 HMAC 挑战 + 防重放；凭据随节点可即时撤销
- 指令只经已认证的活跃连接下发；Agent **零入站监听**（无端口即无扫描面）
- `exec` / `config.apply` / `agent.update` / `docker.op` 在 UI 层强制二次确认（显示目标节点与关键参数摘要）
- 全量审计：`commands`（指令）与 `audit_logs`（面板操作）不可删除
- P1 可选加固：面板可按节点配置 exec 禁用或命令黑名单

### 3.4 凭据与数据存储（→ T9）

| 数据 | 存储方式 |
|---|---|
| 管理员密码 | bcrypt 哈希 |
| 注册 Token | 只存哈希 |
| node_secret | **AES-256-GCM 加密落库**（`nodes.credential_enc`）；加密密钥 = data 目录 `master.key`（首次启动 crypto/rand 生成，权限 0600） |
| SQLite 文件 | 0600；data 目录整体权限收敛 |

备份提示：备份 data 目录须**连同 master.key 一起**（二者缺一不可恢复凭据），且备份件同等保密等级。

### 3.5 Agent 侧

- 本地凭据文件 0600（`server` / `node_id` / `node_secret` 三项而已）
- 权限最小化指引（随文档发布各探测器所需最小权限矩阵）：
  - 仅 docker 探测/容器操作：docker 组即可，无需 root；
  - 配置管理：需目标配置路径写权限 + 对应 reload 权限；
  - systemd 探测：只读即可；
  - 全功能才需要 root，文档明示取舍
- 自更新强制 https + sha256 校验 + 版本禁降级（→ T7）

### 3.6 Web 前端（→ T8）

- 所有动态内容（命令输出、探测 detail、配置内容）渲染时强制转义，探测原始 JSON 以 `<pre>` 文本呈现，绝不 `v-html`
- CSP 禁内联脚本；前端构建产物 SRI 可选
- API 全部 JSON，错误信息不含内部路径/堆栈

### 3.7 分发通道（→ T7）

- install.sh 仅从官方 https 通道拉取；发布产物附 `sha256sums` 文件
- Docker 镜像仅官方仓库发布；文档警告勿用第三方转存镜像
- 中国大陆镜像通道（待定项，见 [03](03-迭代路线图.md) §6.2）确定后必须保持同源校验和

## 4. 爆炸半径与残余风险（坦诚清单）

| 风险 | 说明 | 缓解 / 接受理由 |
|---|---|---|
| 面板失守 = 全节点 RCE | 面板可对全部节点下发 exec，这是产品能力本身 | 账户+会话+防爆破多闸；指令全审计可事后追责；节点凭据可撤销（撤销后 Agent 立即断连）；P2 评估高危指令二次审批/硬件密钥 |
| Agent 高权限运行 | root / docker 组是能力所需 | 零入站监听 + 指令唯一来源已认证连接 + §3.5 最小权限矩阵 |
| master.key 与库同目录 | 全盘失窃时加密防护有限 | 文件权限 + 文档建议宿主盘加密/备份保密；防范的是"仅库文件泄露"场景（如错误地同步了 db 到网盘） |
| SQLite 无整库加密 | 运维数据（配置内容、指令历史）机密度有限 | 敏感字段已单独加密；更高要求交给宿主磁盘加密 |
| 单管理员无分权 | MVP 简化决策 | 全审计兜底；多用户 RBAC 在 P2 |

## 5. 公网部署 Checklist（随产品文档发布）

- [ ] HTTPS 已启用（前置反代 或 面板手动证书；ACME 自动为 P2），HTTP 强制跳转
- [ ] 管理员强密码已设置（≥10 位）；P1 后开启 TOTP
- [ ] 防爆破限流确认开启（默认开启，勿关闭）
- [ ] 条件允许时收敛暴露面：IP 白名单 / WireGuard / Cloudflare Access 前置
- [ ] data 目录定期备份（含 master.key，注意保密）
- [ ] 订阅版本更新，及时升级（面板与 Agent）
- [ ] 不使用的注册 Token 及时撤销

## 6. 安全验证计划（纳入 P0 里程碑，见 03 §5 M1/M5）

| 类别 | 用例 |
|---|---|
| 节点认证 | 伪造 secret、过期 ts、重放 nonce、重放注册 Token、已撤销节点重连（应 4002 断开） |
| 面板认证 | 爆破触发锁定、锁定期内正确密码也拒绝、会话空闲/绝对过期、登出后旧会话失效 |
| Web 安全 | 命令输出含 `<script>` 的 XSS 用例、CSRF 跨站请求拒绝、CSP 头存在性 |
| 指令 | command_id 重复投递幂等、lost 指令不自动重发、exec 超时与输出截断 |
| 更新 | sha256 不匹配拒装、http 下载地址拒绝、降级版本拒绝 |
