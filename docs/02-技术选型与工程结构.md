## 1. 技术栈定稿

### 1.1 后端（面板 + Agent 共用语言）

| 项 | 选型 | 理由 |
|---|---|---|
| 语言 | **Go 1.22+** | 静态编译单二进制（ADR-3/4 的前提）；交叉编译成熟；运维工具生态最对口 |
| WebSocket | gorilla/websocket | 社区事实标准，文档全 |
| HTTP 路由 | go-chi/chi | 轻量、兼容标准库、中间件够用；不引入重框架 |
| SQLite 驱动 | **modernc.org/sqlite** | **纯 Go 实现无 CGO**——这是关键联动决策：`CGO_ENABLED=0` 交叉编译（ADR-4）的前提，绝不能选需要 CGO 的 mattn 驱动 |
| 日志 | log/slog（标准库） | 结构化日志，零依赖 |
| 配置读取 | 标准库 + 环境变量 | 面板：config.yaml + 环境变量覆盖；Agent：极简（`HERD_SERVER` + `HERD_TOKEN`） |

### 1.2 前端（面板）

| 项 | 选型 | 理由 |
|---|---|---|
| 框架 | **Vue 3 + TypeScript + Vite** | 面板类后台的成熟组合；构建产物纯静态，可整体 embed 进 Go 二进制（ADR-5） |
| UI 组件库 | Naive UI | 轻量、TypeScript 友好、暗色主题契合运维面板审美 |
| 图表（P1） | ECharts | 监控历史曲线 |

### 1.3 分发产物清单

| 产物 | 内容 | 目标 |
|---|---|---|
| `moon` 二进制 | 面板（含 embed 前端） | linux/amd64、linux/arm64（按需加 darwin 用于本机开发） |
| `herd` 二进制 | Agent | linux/amd64、linux/arm64、linux/armv7（树莓派类） |
| `moonshepherd` Docker 镜像 | 面板容器形态 | 任意 Docker 机 / Unraid |
| `herd` Docker 镜像 | Agent 容器形态（FROM scratch） | Unraid 等 |
| `install.sh` | Agent 统一安装脚本 | 自动探测 systemd / 无 systemd 环境（§总体设计 3.1） |

## 2. 工程结构规划（未来仓库布局）

```
moonshepherd/                  # 单仓库 monorepo（面板与 Agent 共享协议代码）
├── cmd/
│   ├── moon/                  # 面板入口
│   └── herd/                  # Agent 入口
├── internal/
│   ├── protocol/              # WSS 消息定义（双端共享，唯一耦合点）
│   ├── server/                # 面板：API、WSS 网关、认证、审计
│   ├── agentd/                # Agent 核心：连接管理、心跳、指令执行
│   ├── probe/                 # 探测器插件（docker/nginx/caddy/systemd/unraid 各一文件）
│   ├── executor/              # 指令执行器（exec/config.apply/docker.op/...）
│   └── store/                 # SQLite 访问层（面板侧）
├── web/                       # Vue3 前端源码（构建产物 embed 进 moon 二进制）
├── packaging/
│   ├── Dockerfile.panel
│   ├── Dockerfile.agent
│   ├── docker-compose.yml     # 面板部署样例
│   └── unraid/                # Unraid 自启模板（User Scripts 片段）、远期 .plg
├── docs/                      # 本设计文档集
└── Makefile                   # build / release / docker / cross-compile 目标
```

结构原则：

1. **单仓库**：面板与 Agent 通过 `internal/protocol` 共享消息定义，改协议不会出现双端不同步；
2. **probe/ 每探测器一个文件**：落实"新增应用支持 = 新增一个探测器文件"的渐进式承诺；
3. **store/ 只在面板侧引用**：Agent 永不碰数据库，保持极简。

## 3. 构建与发布

| 环节 | 方案 | 说明 |
|---|---|---|
| 交叉编译 | Makefile（`CGO_ENABLED=0 GOOS=linux GOARCH=…`） | MVP 手动构建即可；无需 goreleaser |
| 前端构建 | Vite → `internal/server/webdist` embed | 开发模式前后端分离热更，发布模式单二进制 |
| 版本规范 | 语义化版本，`moon version` / `herd version` 内嵌 | Agent 自更新（P1）依赖版本比对 |
| 发布通道 | GitHub Releases（或内部对象存储） | install.sh 从该通道拉取；中国大陆节点考虑镜像加速 |
| CI（引入代码后） | GitHub Actions：lint + test + build 产物 | P0 后期再上 |

## 4. 开发环境约束（针对老大的本机）

- 开发机为 Windows + Git Bash：Makefile 目标需兼容（或提供 `build.ps1`/直接 go build 命令文档化）；
- Go 环境通过官方安装包，Node 由 nvm 管理（全局已有约定）；
- SQLite 文件在开发期用 `--data ./data` 指向工作目录，避免污染系统路径。

## 5. 选型上明确"不做"的事

| 不做 | 原因 |
|---|---|
| 不引入 gRPC 做 Agent 通信 | WSS + JSON 信封调试成本低、浏览器可观测；节点规模小，性能无压力 |
| 不用 MySQL/PostgreSQL | 与 ADR-5"部署位置自由"冲突 |
| 不上前端 SSR/Next | 纯静态后台，无 SEO 需求 |
| 不做 Agent 侧插件热加载（动态库） | 静态二进制的核心优势不可破坏；新增探测器 = 发新版 |
| 面板不依赖任何外部服务（Redis/MQ） | 单二进制自包含是硬约束 |
